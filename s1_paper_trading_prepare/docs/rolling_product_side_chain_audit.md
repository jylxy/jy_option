# Rolling Product-Side Chain Audit

Date: 2026-05-29

## Current Paper Chain

`scripts/update_daily_data.py` runs the daily tracking chain:

1. Resolve trading dates.
2. Fetch or reuse `data/daily_snapshots/option_chain_YYYYMMDD.csv`.
3. Build `data/derived/s1_l0_contract_universe_YYYYMMDD.csv`.
4. Materialize locked-panel L1 admission as a parity reference.
5. Upsert `rolling_product_side_observations.csv`.
6. Mature only point-in-time outcome labels whose full future horizon is already stored.
7. Recompute shifted rolling product-side features and write:
   - `rolling_product_side_panel.csv`
   - `rolling_l1_admission_YYYYMMDD.csv`

Order generation still uses the locked mainline panel.  The rolling panel is a tracked replacement candidate only.

## Performance Fixes

The initial long-window run exposed three avoidable costs:

- The locked L1 panel was loaded again for every signal date.
- Fetched snapshots were written twice.
- Rolling outcome labels were recomputed for every historical observation date on every new signal date.

The current implementation fixes those costs:

- Load the locked L1 panel once per update window.
- Write each fetched snapshot once, using atomic CSV replacement.
- Mature only newly eligible observation dates; keep a small snapshot cache for overlapping 10-day future windows.
- Default Toolkit product chunk size is now `32`, with `--product-chunk-size` still available for fallback.

## Research Chain Port

The locked research panel is generated by `server_deploy/scripts/research/build_s1_product_scoring_panel.py`:

```text
aggregate_panel
-> add_derived_factors
-> add_hist_features
-> add_scores
-> add_rank_fields
```

The rolling paper panel now follows that chain field by field where the daily
Toolkit snapshot carries enough information:

- `aggregate_panel`: product-side grouping, eligible row counts, OI depth,
  premium pool, capacity proxy, delta ladder buckets, and mean feature fields.
- `add_derived_factors`: premium density, capacity density, OI density,
  volume/OI, delta-ladder depth, RV contraction, trend magnitude, and IV dulling
  raw inputs.
- `add_hist_features`: shifted rolling labels only. Current-day signals never
  read labels from the same date or from later dates.
- `add_scores`: research weights for capacity, premium quality, regime safety,
  historical retention, tail-cluster safety, and the auxiliary rank fields.
- `add_rank_fields`: date, side-date, and sector-date rank/bucket outputs when
  the source fields are present.

The 5-day product stop-cluster label now follows the full-shadow idea: after the
future horizon is stored, each product is marked stopped if any of its contracts
hit the stop threshold, then the product-side label receives the same-day count
of other stopped products. This label is persisted only after the horizon is
matured, and it enters signals only through a one-row-shifted rolling history.

## Remaining Gap

The current stored Toolkit snapshot has only the daily option-chain fields:

```text
trade_date, option_code, option_close, option_high, volume, open_interest,
strike, option_type, expiry_date, product, exchange, multiplier, dte,
underlying_code, spot_close, moneyness, implied_vol, delta, gamma, vega, theta
```

The locked research table also inherits richer full-shadow and intermediate
fields that are not yet present in the paper datamart, including exact B6 ranks,
exact VRP quality, richer regime and path fields, exact HAR/GARCH/RV inputs, and
the historical research candidate tape. The remaining mismatch is therefore not
from the rolling update mechanism itself; it comes from fields that still need a
clean point-in-time live equivalent before the rolling panel can be promoted into
order generation.

Next action is to backfill or recompute those missing source fields from
Toolkit-accessible history, then rerun the same parity checks before switching
order generation away from the locked mainline panel.
