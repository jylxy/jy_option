# Rolling Product-Side Chain Audit

Date: 2026-05-29

## Current Paper Chain

`scripts/update_daily_data.py` runs the daily tracking chain:

1. Resolve trading dates.
2. Fetch or reuse `data/daily_snapshots/option_chain_YYYYMMDD.csv`.
3. Build `data/derived/s1_l0_contract_universe_YYYYMMDD.csv`.
4. Materialize locked-panel L1 admission as a parity reference.
5. Upsert `rolling_product_side_observations.csv`.
6. Mature only point-in-time outcome labels whose full future horizon is already stored.
7. Recompute shifted rolling product-side features and write:
   - `rolling_product_side_panel.csv`
   - `rolling_l1_admission_YYYYMMDD.csv`

Order generation still uses the locked mainline panel.  The rolling panel is a tracked replacement candidate only.

## Performance Fixes

The initial long-window run exposed three avoidable costs:

- The locked L1 panel was loaded again for every signal date.
- Fetched snapshots were written twice.
- Rolling outcome labels were recomputed for every historical observation date on every new signal date.

The current implementation fixes those costs:

- Load the locked L1 panel once per update window.
- Write each fetched snapshot once, using atomic CSV replacement.
- Mature only newly eligible observation dates; keep a small snapshot cache for overlapping 10-day future windows.
- Default Toolkit product chunk size is now `32`, with `--product-chunk-size` still available for fallback.

## Parity Gap

The locked research panel is generated by `server_deploy/scripts/research/build_s1_product_scoring_panel.py`:

```text
aggregate_panel
-> add_derived_factors
-> add_hist_features
-> add_scores
-> add_rank_fields
```

The important difference is that the research scoring chain uses more full-shadow and derived fields than the current live proxy, including regime safety, side IV/skew changes, term cleanliness, realized-volatility contraction, path/jump/disaster fields, and delta-ladder depth.

Current mature-window comparisons show that the rolling update mechanism is working, but the scoring formula is not yet a full parity replica:

| Window | Key overlap | Gate-ready rows | Gate match |
| --- | ---: | ---: | ---: |
| 2022-02-23 | 48 / 48 | 48 | 75.0% |
| 2022-02-23..2022-03-18 | 894 / 894 | 894 | 75.5% |
| 2022-03-01..2022-03-31 | 1144 / 1144 | 1144 | 74.5% |

Next action is to port the research panel feature-generation chain field by field, especially the tail-cluster and regime-safety inputs, rather than switching the current proxy into order generation.
